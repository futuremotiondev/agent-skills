# Pascal Script

> When to reach for a PascalScript rule, how to write one that survives ReNamer's quirks, how to embed and test it, and
> which ready-made scripts ship with the skill. The API list and engine gotchas are in `engine-notes.md` §2.

## 1. When to use it

Use a script only when native rules can't express the logic:

- **Conditions on name structure** ("pad the number only if the name starts with one", "swap parts only when there are
  exactly three").
- **Cross-file state**: batch size, position in the batch, counts of equal names (`GetTotalNumberOfFiles`,
  `GetCurrentFileIndex`, global `var`s within one preview pass).
- **External lookups**: a dictionary or mapping file read at run time (makes the preset depend on that file; say so).
- **Per-file meta tag formatting** that Insert can't do (`CalculateMetaTagFormat`).
- **Replacing 4+ fragile rules** with one clear script.

Anything a native rule does natively stays native: native rules show their settings in the GUI, and Jay can tweak them
without reading code.

## 2. Writing rules

1. Start from the skeleton below: a header comment saying what it does, a `CONFIG` `const` block at the top (the only part
   Jay should need to edit), and comments for skimmability.
2. **No short-circuit evaluation.** `if (I <= Length(S)) and (S[I] = 'x')` still evaluates `S[I]` and raises "Out of
   string range" at the end of the string. Nest the index access in its own `if` (validator check 12 flags suspects).
3. Strings are 1-based. Use the `Wide*` functions for Unicode safety (`WideExtractBaseName`, `WideUpperCase`, …).
4. `FileName` is the **current new name including the extension** (the output of the previous rules); change it.
   `FilePath` is the original full path, read-only.
5. **No dialogs** (`ShowMessage`, `DialogYesNo`, …) unless the preset is explicitly GUI-only: a modal dialog blocks
   `/silent` runs, droplets and context-menu shortcuts.
6. **No `{$INCLUDE}`**: generated presets are self-contained.
7. Script state resets on **every preview**; globals only persist across files within one pass.

**Skeleton:**
```pascal
{ <Purpose, one or two lines>. Generated by fm-renamer-preset-creator.
  Edit the CONFIG block only. }
const
  // --- CONFIG ---------------------------------------------------------------
  SEPARATOR = ' ';
var
  Base, Ext: WideString;
begin
  Base := WideExtractBaseName(FileName);
  Ext  := WideExtractFileExt(FileName);   // includes the leading dot
  // ... transform Base ...
  FileName := Base + Ext;
end.
```

**Guarded character scan** (the safe shape for rule 2):
```pascal
I := 1;
while I <= Length(Base) do
begin
  if IsWideCharDigit(Base[I]) then   // index access only inside the bounds check
    I := I + 1
  else
    Break;
end;
```

## 3. Embedding

A PascalScript rule has one key, `SOURCEUTF8`: the whole source, UTF-8, lines joined with CRLF, encoded like every other
value. Don't write the source into a JSON string by hand; keep it in a `.pas` file and reference it from the rule:

```json
{ "id": "PascalScript", "comment": "Prefix batch index, padded to the batch size",
  "sourceFile": "batch-index-autowidth.pas" }
```

`sourceFile` is resolved relative to the preset-spec's folder (or the current folder with `-SpecJson`). The builder
strips a UTF-8 BOM (Jay's `.pas` files have one) and normalises line endings to CRLF. The key `SOURCE` (ANSI) belongs
to presets from ReNamer < 7; never emit it.

## 4. Testing recipe

1. Put the script in a preset-spec with fixtures that cover the edge cases (empty match, first/last file, a name that
   must stay unchanged).
2. Build, validate, then run the harness:
   ```powershell
   $b = & scripts/Build-RnpPreset.ps1 -LiteralPath .\my-script.json -OutputDirectory $env:TEMP\rnp-staging
   & scripts/Test-RnpPreset.ps1 -LiteralPath $b.Path
   & scripts/Invoke-RnpProbe.ps1 -Preset $b.Path -Tests .\my-script.json
   ```
3. A compile error shows up as a **non-zero exit code with every name unchanged**; the harness asserts the exit code,
   so it fails loudly. Read the error text by loading the preset in the GUI (Jay) if needed.
4. Scripts with dialogs, or that need two previews, can't run under `/silent`: test everything around them in the
   harness and mark the script's own effect ◻ "verify in GUI".
