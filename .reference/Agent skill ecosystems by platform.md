# One SKILL.md format now spans five rival agent platforms

Every major agent platform outside Anthropic now reads the same unit of capability: a folder containing a `SKILL.md` file with `name` and `description` YAML frontmatter, as defined by the Agent Skills specification at agentskills.io ([agentskills.io/specification](https://agentskills.io/specification)). OpenAI Codex, Google Gemini CLI and Antigravity, GitHub Copilot, Microsoft 365 Copilot and xAI's Grok Build all consume it, and four of the five also converge on `.agents/skills/` as a vendor-neutral project directory, which means a skill written once is installable almost everywhere and the real differences between platforms lie in packaging (plugin manifests), registries, install commands and governance. The platforms split cleanly into two camps. Codex, Gemini/Antigravity, GitHub Copilot and Grok Build are developer CLIs with Git-based plugin marketplaces, open catalogs on GitHub (`openai/skills` and `openai/plugins`, `gemini-cli-extensions`, `github/awesome-copilot` with **40.4k stars**, `xai-org/plugin-marketplace` with **36 plugins**) and a shared "Agent Plugins" manifest (`plugin.json` with the `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json` schema) that Codex, Copilot and Microsoft all document. Microsoft 365 Copilot is the outlier: it wraps `SKILL.md` inside a tenant-governed Teams-style app package (`manifest.json` with `agentSkills[]`, `declarativeAgent.json` schema v1.9 with `agent_skills[]`), distributes agents through an authenticated Agent Store and AppSource, and has no public skill catalog at all. Across all of them, Vercel's `npx skills add <owner/repo>` installer and the skills.sh directory (**79 supported agents**, **1,496,597 all-time installs** on the leaderboard) act as the de facto cross-platform registry, GitHub topic `agent-skills` (**15,558 repositories**) is the broadest discovery tag, and the only reliable verification of a candidate is structural: a valid `SKILL.md` frontmatter in a documented load path, a vendor manifest that the platform's own validator accepts (`gh skill publish --dry-run`, `grok plugin validate .`, `wiqd agent validate`, `skills-ref validate`), and provenance from an official org or a SHA-pinned catalog entry. Several facts below were flagged by the researchers as unverified and remain so here: the Grok `--trust` flag's exact semantics, whether `~/.codex/skills` is still read, whether a public source repo exists for Google's `antigravity-plugins-official` marketplace, and the existence of the aggregator "tonsofskills" as a cross-platform index (it exists, but as a Claude-centric directory).

## OpenAI Codex and ChatGPT: Agent Skills plus a plugin layer shared with ChatGPT

### Official registries and marketplaces

OpenAI's original skills catalog is `https://github.com/openai/skills`, organized into three tiers: `skills/.system` (auto-installed in current Codex builds), `skills/.curated` (passed OpenAI review) and `skills/.experimental` (prototypes). As of Codex v0.130.0 the system tier held five skills, `skill-installer`, `skill-creator`, `plugin-creator`, `openai-docs` and `imagegen`, and the curated tier held **38 named skills** including `gh-fix-ci`, `gh-address-comments`, `cloudflare-deploy`, `vercel-deploy`, `netlify-deploy`, `render-deploy`, `figma`, `linear`, `notion-*`, `sentry`, `playwright`, `pdf`, `chatgpt-apps`, `aspnet-core` and `winui-app`; the repo had **19,000+ stars** ([Daniel Vaughan, "Official OpenAI Skills Catalogue"](https://codex.danielvaughan.com/2026/05/14/openai-skills-catalogue-codex-cli-official-curated-experimental-skill-installer/)). Its README now marks the repo deprecated and states that "The OpenAI Plugins repository (https://github.com/openai/plugins) is now the main source for Codex skill and plugin examples" ([DocSearch mirror of openai/skills README](https://docsearch.algolia.com/mcp/docs/repo/openai/skills)). The `openai/plugins` repo carries a catalog registry at `.agents/plugins/marketplace.json` and a `plugins/` root with per-plugin folders such as `linear`, `atlassian-rovo`, `google-calendar`, `gmail`, `slack` and `zotero`, each containing `.codex-plugin/plugin.json`, `skills/<skill-name>/SKILL.md`, `.app.json` and `.mcp.json` ([instagit summary of openai/plugins](https://instagit.com/openai/plugins/how-is-the-openai-plugins-repository-organized.md)). The researcher could not fetch either GitHub repo directly, so the exact current plugin list in `openai/plugins` is unverified, and no official source confirms whether `openai/plugins` is pre-registered as a default marketplace in Codex.

Public distribution runs through a universal plugin directory shared by ChatGPT and Codex. Developers upload a ZIP in the Plugins dashboard at `https://platform.openai.com/plugins`; "Your plugin can include MCP connections, skills, or both"; the submission doc is `https://developers.openai.com/plugins/deploy/submission` ([OpenAI plugin submission page](https://developers.openai.com/apps-sdk/deploy/submission)). End users install from the Plugins Directory in the ChatGPT desktop app or via `/plugins` in Codex; official docs give no CLI install command ([OpenAI "Build plugins"](https://developers.openai.com/codex/plugins/build.md)). ChatGPT Apps (Apps SDK, directory at `chatgpt.com/apps`, submission at `https://platform.openai.com/apps-manage`) are a separate product and are out of scope for skill discovery unless they ship a plugin with a `skills/` folder ([OpenAI, "Developers can now submit apps to ChatGPT"](https://openai.com/index/developers-can-now-submit-apps-to-chatgpt/)); whether `apps-manage` and `plugins` have been unified is not confirmed.

### Skill, plugin and extension formats and manifest filenames

Codex uses the open Agent Skills standard. A skill is a directory with a `SKILL.md` whose frontmatter must include `name` and `description`, plus optional `scripts/`, `references/`, `assets/` and a Codex-specific `agents/openai.yaml`; the official doc states skills build on "the open agent skills standard" at agentskills.io, and Codex loads only name and description until the skill is selected ([OpenAI "Build skills"](https://learn.chatgpt.com/docs/build-skills)). The `agents/openai.yaml` file carries `interface` (`display_name`, `short_description`, `icon_small`, `icon_large`, `brand_color`, `default_prompt`), `policy` (`allow_implicit_invocation`, default `true`) and `dependencies.tools` entries with `type`, `value`, `description`, `transport`, `url` ([OpenAI "Build skills"](https://learn.chatgpt.com/docs/build-skills)). The researcher notes this file is the most Codex-specific filename and the best discriminator between a generic Agent Skill and one tuned for Codex.

Plugins are a newer packaging layer. The portable manifest is `plugin.json` at the plugin root with `$schema` set to `"https://agent-plugins.org/schemas/1.0.0/plugin.schema.json"`, `name` (kebab-case), `version`, `description`, and OpenAI settings under `extensions["com.openai"]` (`apps` pointing to `./.app.json`, `hooks`, `interface`, `onboardingSkill`); `.codex-plugin/plugin.json` is an optional compatibility overlay that applies only when `extensions.com.openai` is absent from the root manifest ([OpenAI "Package your plugin"](https://developers.openai.com/plugins/build/plugins.md); [OpenAI "Build plugins"](https://developers.openai.com/codex/plugins/build.md)). The portable layout is `my-plugin/` containing `plugin.json`, `mcp.json`, `skills/<skill-name>/SKILL.md`, `assets/`, `.app.json`, `hooks/hooks.json` and optionally `.codex-plugin/plugin.json`; the `@plugin-creator` scaffold instead emits `.codex-plugin/plugin.json`, `.mcp.json` and `.app.json`, and the docs warn "Don't just rename `.mcp.json` to `mcp.json`. The portable format requires a transport `type` per server" ([OpenAI "Build plugins"](https://developers.openai.com/codex/plugins/build.md)). Marketplace files live at `$REPO_ROOT/.agents/plugins/marketplace.json` (repo), `~/.agents/plugins/marketplace.json` (personal) and, as a legacy-compatible location, `$REPO_ROOT/.claude-plugin/marketplace.json`; each `plugins[]` entry needs `name`, `source`, `policy` (`installation`, `authentication`) and `category`, with source types `local`, `url`, `git-subdir` and `npm` and installation policies `AVAILABLE`, `INSTALLED_BY_DEFAULT`, `NOT_AVAILABLE` ([OpenAI "Package your plugin"](https://developers.openai.com/plugins/build/plugins.md)). Because the manifest shape evolved during 2026 (an earlier `components`/`install_policy` form existed in v0.117.0+), a discovery tool should accept either manifest filename and not rely on a fixed internal field set ([Daniel Vaughan, "Codex CLI Customisation Stack"](https://codex.danielvaughan.com/2026/04/12/codex-cli-customisation-stack-unified-system/)).

`AGENTS.md` is the always-on companion, not a skill: Codex loads the global `~/.codex/AGENTS.md` and then walks from repo root to CWD checking `AGENTS.override.md`, then `AGENTS.md`, then `project_doc_fallback_filenames`, concatenating up to `project_doc_max_bytes` (default 32 KiB) ([Codex AGENTS.md guide](https://developers.openai.com/codex/guides/agents-md)). Custom subagents are `.codex/agents/*.toml` files ([Daniel Vaughan, 2026-04-12](https://codex.danielvaughan.com/2026/04/12/codex-cli-customisation-stack-unified-system/)).

### Directory load paths

The official doc lists six skill scopes: `$CWD/.agents/skills` (REPO), `$CWD/../.agents/skills` (REPO, a folder above CWD inside a Git repo), `$REPO_ROOT/.agents/skills` (REPO), `$HOME/.agents/skills` (USER), `/etc/codex/skills` (ADMIN) and skills bundled with Codex (SYSTEM); Codex scans `.agents/skills` from CWD up to the repo root, follows symlinked skill folders, and does not merge two skills that share a `name` ([OpenAI "Build skills"](https://learn.chatgpt.com/docs/build-skills)). The official doc does not list `~/.codex/skills`, `$CODEX_HOME/skills` or `.codex/skills`, yet the `openai/skills` README says `$skill-installer` installs to `$CODEX_HOME/skills/`, "defaulting to `~/.codex/skills/`", and the awesome-codex-skills README says the same ([Daniel Vaughan, 2026-05-14](https://codex.danielvaughan.com/2026/05/14/openai-skills-catalogue-codex-cli-official-curated-experimental-skill-installer/); [GitTrend page for ComposioHQ/awesome-codex-skills](https://gittrend.io/repo/ComposioHQ/awesome-codex-skills)). Whether current Codex builds still read `~/.codex/skills` is unverified; the researcher's inference is that the discrepancy reflects a 2026 migration and that a tool should scan both. Precedence order among the REPO/USER/ADMIN/SYSTEM scopes is not stated in the official doc. Installed plugins are cached at `~/.codex/plugins/cache/$MARKETPLACE_NAME/$PLUGIN_NAME/$VERSION/`, and repo enablement goes in `.codex/config.toml` under the key `plugin-name@marketplace-name` ([OpenAI "Package your plugin"](https://developers.openai.com/plugins/build/plugins.md)). Skills can be disabled without deletion in `~/.codex/config.toml` via `[[skills.config]]` / `path = "/path/to/skill/SKILL.md"` / `enabled = false`, and `skills.max_context_tokens` caps the initial skills list at up to 10,000 tokens ([OpenAI "Build skills"](https://learn.chatgpt.com/docs/build-skills)).

### Install CLI commands

Skills install in-session through the system skill: `$skill-installer gh-address-comments` (curated, by name), `$skill-installer install skills/.experimental/create-plan` (by path) and `$skill-installer install https://github.com/openai/skills/tree/main/skills/.experimental/create-plan` (by GitHub directory URL), followed by a Codex restart; `$skill-installer list` shows installed skills, and the underlying script is `python install-skill-from-github.py --ref v1.2.0 --dest /custom/path --method git --name my-skill` ([DocSearch mirror of openai/skills README](https://docsearch.algolia.com/mcp/docs/repo/openai/skills); [Daniel Vaughan, 2026-05-14](https://codex.danielvaughan.com/2026/05/14/openai-skills-catalogue-codex-cli-official-curated-experimental-skill-installer/)). The official doc example is `$skill-installer linear`, and skills are created with `$skill-creator` in Codex or `@skill-creator` in ChatGPT Work; in the CLI or IDE extension, `/skills` or typing `$` invokes a skill explicitly ([OpenAI "Build skills"](https://learn.chatgpt.com/docs/build-skills)). Plugin marketplaces are managed with `codex plugin marketplace add owner/repo`, `codex plugin marketplace add owner/repo --ref main`, `codex plugin marketplace add https://github.com/example/plugins.git --sparse .agents/plugins`, `codex plugin marketplace add ./local-marketplace-root`, `codex plugin marketplace list`, `codex plugin marketplace upgrade [marketplace-name]` and `codex plugin marketplace remove marketplace-name`; plugins are then installed from the Plugins Directory or scaffolded with `$plugin-creator` ([OpenAI "Build plugins"](https://developers.openai.com/codex/plugins/build.md)). Third-party sources add slash forms `/plugin marketplace add openai/codex-plugin-cc`, `/plugin install codex@openai-codex`, `/reload-plugins` and pinning with `@branch` or `#tag`, and date the marketplace launch to 27 March 2026 ([Daniel Vaughan, "Codex Marketplace"](https://codex.danielvaughan.com/2026/04/11/codex-marketplace-plugin-distribution/)); `openai/codex-plugin-cc` could not be verified as a real repo, and whether `codex plugin install <name>` exists as a CLI subcommand is not documented officially. The cross-agent path is `npx skills add <owner>/<repo>` with `-a codex`; the exact directory the `skills` CLI writes to for the `codex` target was not confirmed (expected `.agents/skills`).

### MCP configuration

MCP servers are declared as `[mcp_servers.<name>]` TOML tables in `~/.codex/config.toml`, or in project `.codex/config.toml` for trusted projects only. STDIO servers use `command` (required), `args`, `env`, `env_vars`, `cwd`; Streamable HTTP servers use `url` (required), `auth`, `bearer_token_env_var`, `http_headers`, `env_http_headers`; shared keys include `startup_timeout_sec` (default `10`), `tool_timeout_sec` (default `60`), `enabled`, `required`, `enabled_tools`, `disabled_tools`, `default_tools_approval_mode` and per-tool `tools.<tool>.approval_mode` ([OpenAI MCP doc](https://learn.chatgpt.com/docs/extend/mcp.md)). The CLI offers `codex mcp add <server-name> --env VAR1=VALUE1 -- <stdio server-command>`, `codex mcp list`, `codex mcp login <server-name>` and `codex mcp login <name> --scopes read,write`; `/mcp` in the TUI shows active servers; the desktop app, CLI and IDE extension share one MCP configuration, while ChatGPT web uses plugins for remote MCP and does not read local Codex config ([OpenAI MCP doc](https://learn.chatgpt.com/docs/extend/mcp.md)). Plugins carry MCP in `mcp.json` with servers under `mcpServers`, each with a transport `type` such as `"streamable-http"` and `url`, and per-server auth under `extensions["com.openai"].auth` (`none`, `oauth`, `mixed`, `api_key`) ([OpenAI "Package your plugin"](https://developers.openai.com/plugins/build/plugins.md)). The official page does not document `codex mcp get`, `codex mcp remove`, `codex mcp logout` or a `codex mcp-server` mode, so those remain unverified.

### How to verify a candidate is real

A genuine Codex skill contains `SKILL.md` with `name` (lowercase and hyphens, matching the folder) and `description`; lives at `.agents/skills/<name>/`, `/etc/codex/skills/<name>/`, or `skills/<name>/` inside a plugin that has `plugin.json` or `.codex-plugin/plugin.json` (legacy `~/.codex/skills/<name>/` also seen); optionally carries `agents/openai.yaml`; and is installable by `$skill-installer <name|path|URL>`, `npx skills add <owner>/<repo> [--skill <name>]`, manual copy or `codex plugin marketplace add owner/repo` plus `/plugins`. Provenance signals are membership in `openai/skills` `.system`/`.curated` tiers, `openai/plugins`, a vendor org repo such as `supabase/agent-skills` or `vercel-labs/agent-skills`, or `ComposioHQ/awesome-codex-skills`, with aggregator security scores available on skills.cat. The spec validator is `npx skills-ref validate ./my-skill` ([Daniel Vaughan, 2026-05-05](https://codex.danielvaughan.com/2026/05/05/agent-skills-open-standard-portable-skills-codex-cli-cross-agent/)). A documentation caveat matters for any tool that cites sources: every `developers.openai.com/codex/...` doc URL fetched on 2026-10-24 returned a 302 to `learn.chatgpt.com/docs/...` (for example `developers.openai.com/codex/skills` to `learn.chatgpt.com/docs/build-skills`), while plugin docs at `developers.openai.com/codex/plugins/build.md` did not redirect, and appending `.md` returns raw Markdown.

## Google Gemini CLI and Antigravity: two ecosystems during a forced migration

The context that reframes everything in this section is that Google announced on **May 19, 2026** that Gemini CLI is being folded into Antigravity CLI (`agy`), and on **June 18, 2026** Gemini CLI stopped serving requests for consumer and free tiers; it remains open source and usable with paid API keys or Code Assist Standard and Enterprise licences, and Gemini CLI "extensions" live on as Antigravity "plugins" ([Google Developers Blog, May 19 2026](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli)). A discovery tool therefore has to crawl both the legacy Gemini CLI extension ecosystem, which is still large and indexed, and the Antigravity plugin and skill ecosystem.

### Official registries and marketplaces

Gemini CLI's gallery is `https://geminicli.com/extensions/` with the browse page at `https://geminicli.com/extensions/browse/`, which on Oct 24 2026 read "Search all **2194** extensions", showed cards with `@owner/repo`, component tags (`MCP`, `Context`, `Commands`, `Skills`, `Hooks`) and star counts, and carried the banners "Unpaid tier and Google One users: Gemini CLI was replaced by Antigravity CLI on June 18th, 2026" and "Gemini CLI has not been optimized for Gemini 4 Argon" ([geminicli.com/extensions/browse](https://geminicli.com/extensions/browse/)). The gallery is not a submission queue; "The Gemini CLI extension gallery automatically indexes public extensions" that (1) are public GitHub repos, (2) carry the GitHub topic `gemini-cli-extension` ("Our crawler uses this topic") and (3) have `gemini-extension.json` at the absolute root of the repo or release archive, crawled daily "if it passes validation" ([releasing.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/extensions/releasing.md)). Google's first-party extensions live in the GitHub org `https://github.com/gemini-cli-extensions` ("Google Extensions for Gemini CLI", **48 repositories**), with repos such as `conductor` (3.8k stars, described as "A plugin for AI coding agents (Antigravity, Claude Code)"), `nanobanana`, `security`, `workspace`, `code-review`, `stitch`, `sre`, `cicd`, `bigquery-conversational-analytics`, `vertex` and `google-secops` ([GitHub org: gemini-cli-extensions](https://github.com/gemini-cli-extensions)); only 16 of the 48 were visible because the GitHub API was blocked.

Antigravity's registry is the `antigravity-plugins-official` marketplace, accessed from inside `agy` via `/plugin` (alias `/plugins`), which opens a Plugins Manager with Discover and Installed tabs; observed first-party plugins include `firebase`, `flutter` (v1.0.5, 23 skills, agent `a11y_agent.md`, MCP `dart-mcp-server`), `gdocs`, `google_slides`, `gsheets`, `gcalendar` and `workspace`, with "Discover (15)" plugins at the time of the screenshot ([Antigravity Docs: Marketplace](https://antigravity.google/docs/marketplace?tab=cli); [Antigravity Docs: Plugins](https://antigravity.google/docs/cli/plugins)). Listing in the Antigravity Marketplace is by interest form (`https://forms.gle/2EX5RFYPoJe1UgxR9`), not an open crawl, and the "Build with Google" page at `https://antigravity.google/docs/build-with-google` curates plugins for Firebase, Android, Flutter, Chrome DevTools and BigQuery ([Antigravity Docs: Marketplace](https://antigravity.google/docs/marketplace?tab=cli)). **No public GitHub URL for the `antigravity-plugins-official` marketplace source was found in any fetched page; whether one exists is unverified.** The community-forum repo `https://github.com/google-antigravity/antigravity-cli` (initialized May 19 2026, release 1.4.7 on Oct 24 2026, 2.6k stars) contains only `README.md`, `CHANGELOG.md` and `examples/`, so the `agy` binary appears closed-source ([GitHub: google-antigravity/antigravity-cli](https://github.com/google-antigravity/antigravity-cli)).

### Skill, plugin and extension formats and manifest filenames

Both platforms use the Agent Skills standard. Gemini CLI's docs say a skill is "Based on the [Agent Skills](https://agentskills.io) open standard" ([skills.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/skills.md)), and Antigravity's doc opens "Skills are an open standard for extending agent capabilities. A skill is a folder containing a `SKILL.md` file with instructions" ([Antigravity Docs: Agent skills](https://antigravity.google/docs/skills)). Antigravity diverges from the spec on one point: `name` is not required and "Defaults to the folder name if not provided", while `description` is required; its canonical layout is `SKILL.md` plus optional `scripts/`, `examples/`, `resources/` ([Antigravity Docs: Agent skills](https://antigravity.google/docs/skills)). A third-party cheat sheet tested on agy 1.2.4 also lists a single-file `.agents/skills/<name>.md` form, which is not in the official doc ([computingforgeeks Antigravity CLI cheat sheet](https://computingforgeeks.com/antigravity-cli-cheat-sheet/)). Whether Antigravity enforces the spec's optional `license`, `allowed-tools` and `metadata` fields is not documented.

Gemini CLI extensions require `gemini-extension.json` in the repo root with fields `name` (lowercase, numbers, dashes, expected to match the directory), `version`, `description`, `migratedTo`, `mcpServers` (all MCP options except `trust`, using `${extensionPath}`), `contextFileName` (defaults to `GEMINI.md`), `excludeTools`, `plan.directory`, `settings[]` and `themes[]`; inside the extension, `commands/*.toml` become slash commands (`commands/gcs/sync.toml` becomes `/gcs:sync`), `hooks/hooks.json`, `skills/<name>/SKILL.md`, `agents/*.md` (preview) and `policies/*.toml` ([reference.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/extensions/reference.md)). Antigravity plugins replace this with `plugin.json`, "Required marker and manifest file", in a layout of `plugins/<plugin-name>/` containing `plugin.json`, `mcp_config.json`, `hooks.json`, `skills/<skill-name>/SKILL.md`, `agents/<agent-name>.md` and `rules/<rule-name>.md`; the manifest example is `{"$schema": "https://antigravity.google/schemas/v1/plugin.json", "name": "my-custom-plugin", "description": "..."}`, `name` must match `^[a-zA-Z0-9-_]+$` and the schema has `additionalProperties: false` ([Antigravity Docs: Plugins](https://antigravity.google/docs/cli/plugins)). Always-on context is `GEMINI.md` (hierarchical, importable via `@./components/instructions.md`, renameable through `settings.json` `{"context": {"fileName": ["AGENTS.md", "CONTEXT.md", "GEMINI.md"]}}`) for Gemini CLI ([gemini-md.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/gemini-md.md)), and for Antigravity `AGENTS.md` or `GEMINI.md` are interchangeable rules, with modular `.agents/rules/*.md` files carrying `trigger: always_on | model_decision | glob | manual`, 24,000 bytes per file and a 20,000-token aggregate budget ([Antigravity Docs: Rules](https://antigravity.google/docs/rules)). Gemini Code Assist for GitHub and Jules use neither: Code Assist reads `.gemini/config.yaml` plus a `styleguide.md` (exact `.gemini/styleguide.md` path unverified) ([Google Cloud docs](https://docs.cloud.google.com/gemini/docs/code-review/customize-repo-review)), and Jules reads a root `AGENTS.md` ([Jules docs](https://jules.google/docs)).

### Directory load paths

Gemini CLI loads skills in four tiers of rising precedence: built-in, extension skills, user skills in `~/.gemini/skills/` or the `~/.agents/skills/` alias, and workspace skills in `.gemini/skills/` or the `.agents/skills/` alias, where "the `.agents/skills/` alias takes precedence over the `.gemini/skills/` directory" within a tier ([skills.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/cli/skills.md)). Extensions install to `~/.gemini/extensions/<name>`, with install metadata in `~/.gemini/extensions/<name>/.gemini-extension-install.json` ([reference.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/extensions/reference.md); [releasing.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/extensions/releasing.md)). Antigravity's paths differ per surface. The App reads `<workspace-root>/.agents/skills/<skill-folder>/` and `~/.gemini/config/skills/<skill-folder>/`; the CLI reads `<workspace-root>/.agents/skills/<skill-folder>/`, `~/.gemini/antigravity-cli/skills/<skill-folder>/` and `~/.gemini/antigravity-cli/plugins/<name>/skills/`; the IDE reads the App paths plus legacy `~/.gemini/antigravity/skills/` ([Antigravity Docs: Agent skills](https://antigravity.google/docs/skills)). Google's codelab adds a trap: the third-party installer default `~/.agents/skills` is picked up by Antigravity App but **not** by Antigravity CLI ([Codelab: Authoring Google Antigravity Skills](https://codelabs.developers.google.com/getting-started-with-antigravity-skills?hl=en)). Plugins sit at `~/.gemini/antigravity-cli/plugins/<plugin_name>/` for the CLI and `.agents/plugins/` (workspace) or `~/.gemini/config/plugins/` (global) for App and IDE ([Antigravity Docs: Plugins](https://antigravity.google/docs/cli/plugins)). The directory is `.agents/` (plural); the singular `.agent/rules/*.md` is a legacy rules path only ([Antigravity Docs: Rules](https://antigravity.google/docs/rules)).

### MCP configuration

Gemini CLI declares servers inline under `mcpServers` in `~/.gemini/settings.json` or in an extension's `gemini-extension.json`, with settings.json winning on name conflicts; in-session commands are `/mcp list` and `/mcp` ([reference.md](https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/extensions/reference.md)). The `~/.gemini/settings.json` location is cited from the Antigravity migration page rather than Gemini CLI's own configuration doc. Antigravity moves MCP to a standalone file: global `~/.gemini/config/mcp_config.json` and workspace `<workspace>/.agents/mcp_config.json`, with a root `mcpServers` map in which each server has `command` (stdio) or `serverUrl` (Streamable HTTP; "You can also use `url`"), plus `args`, `env`, `cwd`, `headers`, `authProviderType` (`"google_credentials"`), `oauth`, `disabled`, `enabledTools`, `disabledTools` and `timeoutSeconds`; legacy `url`/`httpUrl` keys must be renamed to `serverUrl`, which `agy plugin import gemini` does automatically ([Antigravity Docs: MCP](https://antigravity.google/docs/mcp); [Antigravity Docs: Migrating from Gemini CLI](https://antigravity.google/docs/gcli-migration)). OAuth tokens live at `~/.gemini/antigravity/mcp_oauth_tokens.json`, and permission syntax is `mcp(server/tool)`, `mcp(server/*)`, `mcp(*)` ([Antigravity Docs: MCP](https://antigravity.google/docs/mcp)). Shell commands `agy mcp add fs npx -y @modelcontextprotocol/server-filesystem /work` and `agy mcp list|enable|disable|remove <name>` come from the third-party cheat sheet only and are **not confirmed on the official page**, which shows the `/mcp` TUI manager and manual file edits.

### How to verify a candidate is real

For a skill, confirm `SKILL.md` exists with YAML frontmatter containing `description` (required by both Antigravity and the spec). For a Gemini CLI extension, confirm `gemini-extension.json` at the repo root with `name` matching the directory; presence in the geminicli.com gallery implies it passed Google's validator. For an Antigravity plugin, confirm `plugin.json` with `name` matching `^[a-zA-Z0-9-_]+$`; `agy plugin list --json` after install enumerates its skills, agents, rules, MCP servers and hooks. Treat three indicator files as "Antigravity-compatible": a `plugin.json` referencing `antigravity.google/schemas/v1/plugin.json`, any `.agents/skills/*/SKILL.md`, and a legacy `gemini-extension.json` (importable with `agy plugin import gemini`). Google-authored entries are recognizable by `@gemini-cli-extensions/...`, `@googleworkspace/...` and `@GoogleCloudPlatform/...` handles; whether the gallery marks first-party status with a badge is unverified. Every `antigravity.google/docs/...` page exposes a `.md` twin (for example `https://antigravity.google/docs/skills.md`), and the raw Gemini CLI docs under `https://raw.githubusercontent.com/google-gemini/gemini-cli/main/docs/` are the most crawler-friendly source.

## Microsoft 365 Copilot: SKILL.md wrapped in tenant-governed app packages

Microsoft 365 Copilot (the work Copilot in Teams, Word, Outlook and the Microsoft 365 Copilot app) is a different product from GitHub Copilot, and its extensibility model is the odd one out in this report: there is no standalone skill unit, no public skill catalog, and every artifact is deployed through a Teams-style app package governed by a tenant administrator.

### Official registries and marketplaces

End users acquire agents from the in-product Agent Store, "the central hub in Microsoft Copilot where you can easily discover and install agents", with collections for prebuilt agents, "Built by your org" and "Agents for your team" (Agent 365); it is reachable across Teams, Outlook, Word, Excel and PowerPoint but requires a tenant login ([Set up Agent Store in Microsoft Copilot](https://learn.microsoft.com/microsoft-365/copilot/copilot-agent-store)). ISVs publish through Partner Center's "Microsoft 365 and Copilot" program, which "consolidates the former Microsoft Teams Store, Office Store, and AppSource for Microsoft 365"; apps published to the Teams Store "are automatically listed on the Microsoft Commercial Marketplace" at `https://appsource.microsoft.com/`, and "Only declarative and custom agents built with the Microsoft 365 Agents Toolkit suite of tools can be submitted" ([Ecosystem](https://learn.microsoft.com/microsoft-365/copilot/extensibility/ecosystem#unified-app-model); [Agents admin guide](https://learn.microsoft.com/microsoft-365/copilot/agent-essentials/m365-agents-admin-guide#set-agent-policies)). Admins gate everything in the Microsoft 365 admin center under **Agents > All agents** (the Agent Registry) and **Agents > Tools > Registry**, where "Plugins: Installable packages that bundle capabilities an agent can use, such as skills, MCP servers, and connectors" and standalone skills are uploaded as manifests ([Overview of the Tools page](https://learn.microsoft.com/microsoft-agent-365/admin/agent-tools-overview); [Manage plugins, skills, and MCP servers](https://learn.microsoft.com/microsoft-365/admin/manage/manage-plugins-skills-mcp-servers?view=o365-worldwide)). The 2026 plugin model adds `wiqd plugin share --scope users|tenant`, which places a plugin in **Cowork > Sources & Skills > Plugins > Shared with me**, but "The plugin surface doesn't provide public-store submission or a `wiqd plugin publish` command" ([Publish or share your plugin](https://learn.microsoft.com/microsoft-365/copilot/extensibility/publish); [Compare tools for declarative agents](https://learn.microsoft.com/microsoft-365/copilot/extensibility/declarative-agent-tool-comparison#work-iq-dev-tools)). The Agent Library inside Copilot Agent Kit (April 2026 release) offers prebuilt templates with GitHub source at `https://github.com/microsoft/m365-agent-templates` ([Agent Library](https://learn.microsoft.com/en-us/microsoft-copilot-studio/guidance/kit-agent-library)). No documented REST or Graph API for enumerating Agent Store or AppSource agent listings was found, and no verified AppSource deep link filtered to Copilot agents was captured; the researcher's inference is that AppSource is the only public, unauthenticated web surface.

### Skill, plugin and extension formats and manifest filenames

The deployable unit is a Microsoft 365 app package, "a zip file that contains one or more configuration (manifest) files and your app icons" ([Copilot extensibility in the Microsoft 365 ecosystem](https://learn.microsoft.com/microsoft-365/copilot/extensibility/ecosystem#unified-app-model)). Its `manifest.json` uses the Teams app manifest schema (for example `"$schema": "https://developer.microsoft.com/json-schemas/teams/v1.28/MicrosoftTeams.schema.json"`, `"manifestVersion": "1.28"`) and references agents through `copilotAgents.declarativeAgents[]` objects `{ "id": "agent1", "file": "declarativeAgent1.json" }`, skills through `"agentSkills": [ { "folder": "./skills/contract-analysis" } ]`, and MCP connectors through `agentConnectors[]` with `toolSource.remoteMcpServer.mcpServerUrl`; icons are `color.png` (192×192) and `outline.png` (32×32), and the v1.28 schema "sets `additionalProperties: false` at the root" ([declarativeAgentRef object](https://learn.microsoft.com/en-us/microsoft-365/extensibility/schema/declarative-agent-ref); [Build plugins for Copilot Cowork](https://learn.microsoft.com/microsoft-365/copilot/cowork/cowork-plugin-development)). The declarative agent manifest is at schema **version 1.9**, JSON Schema `https://developer.microsoft.com/json-schemas/copilot/declarative-agent/v1.9/schema.json`, with required `version` (`v1.9`), `name` (≤100 chars), `description` (≤1,000) and `instructions` (≤8,000), and optional `capabilities`, `conversation_starters` (≤12), `actions` (1–10 plugin refs), `agent_skills` (≤8), `worker_agents` and more; 1.9 "Added the new top-level `agent_skills` property, which references skill directories that follow the Agent Skills standard" ([Declarative agent schema 1.9](https://learn.microsoft.com/microsoft-365/copilot/extensibility/declarative-agent-manifest-1.9)). API and MCP plugins (actions) use a plugin manifest with `"schema_version": "v2.4"`, required `name_for_human`, `namespace` and `description_for_human`, and `runtimes[].type` of `OpenApi`, `LocalPlugin` or `RemoteMCPServer`, schema at `https://developer.microsoft.com/json-schemas/copilot/plugin/v2.4/schema.json` ([Plugin manifest schema 2.4](https://learn.microsoft.com/microsoft-365/copilot/extensibility/plugin-manifest-2.4)). TypeSpec (`main.tsp` with `@agent`, `@instructions`, `@capabilities`, `@actions`) compiles to the same JSON ([TypeSpec overview](https://learn.microsoft.com/microsoft-365/copilot/extensibility/overview-typespec#get-started)).

The word "plugin" has two meanings in Microsoft's own docs: the technical MCP or API action used by a declarative agent, and the customer-facing "Microsoft 365 Copilot plugin", "an installable package that brings together capabilities for a specific task" that can include agents, skills, connectors and remote MCP references, where "The plugin is the unit of extensibility; the skill remains a distinct reusable capability" ([MCP and API plugins for declarative agents](https://learn.microsoft.com/microsoft-365/copilot/extensibility/overview-plugins); [What is a Microsoft 365 Copilot plugin?](https://learn.microsoft.com/microsoft-365/copilot/extensibility/plugins-overview)). Skills themselves are genuine Agent Skills: "Skills use the Agent Skills open standard—the same format supported by Claude Code, Visual Studio Code Copilot, Gemini CLI, Cursor, JetBrains Junie, and 30+ other AI tools", packaged as `manifest.json` + `color.png` + `outline.png` + `skills/<name>/SKILL.md` ([Build plugins for Copilot Cowork](https://learn.microsoft.com/microsoft-365/copilot/cowork/cowork-plugin-development)). But M365 adds hard limits absent elsewhere: custom skills in declarative agents are "in preview for organizations that are part of the Microsoft Frontier Preview", capped at 8 skills per agent, ≤350 files, directory depth ≤3, `SKILL.md` instructions "must be under 20,000 characters", scripts run in a sandbox with "no network access at runtime", "Reuse across agents: Not supported at this stage of the preview", and "ISVs shouldn't submit declarative agent packages that include custom skills to Partner Center" ([Custom skills in declarative agents (preview)](https://learn.microsoft.com/microsoft-365/copilot/extensibility/declarative-agent-skills)). Copilot Studio's 2026 "Skills" component uses the same definition for "Agents powered by the GitHub Copilot harness", while older "skills" meant actions, Bot Framework skill bots, "Office skills" or an Excel add-in sample, so a tool should key on `SKILL.md` plus `agentSkills`/`agent_skills`, not the word ([Skills overview for agents](https://learn.microsoft.com/microsoft-copilot-studio/agents-experience/skills-overview)). The unrelated Microsoft Security Copilot uses `AgentManifest.yaml` and `PackageManifest.yaml` ([Publish your Security Copilot agent](https://learn.microsoft.com/azure/sentinel/isv/publish-agent-to-security-store#troubleshooting)).

### Directory load paths

There is no filesystem load path in the Codex or Copilot sense; skills load from inside the uploaded package, and "The system stores uploaded skill files in tenant-scoped SharePoint Embedded containers" ([Custom skills in declarative agents](https://learn.microsoft.com/microsoft-365/copilot/extensibility/declarative-agent-skills)). The source-tree conventions are the discoverable paths: Agents Toolkit projects place the agent manifest at `appPackage/declarativeAgent.json` and scaffold skills to `./appPackage/skills/your-skill-name/SKILL.md` ([Add knowledge sources](https://learn.microsoft.com/microsoft-365/copilot/extensibility/build-declarative-agents-add-knowledge#add-a-copilot-connector-to-the-agent); [Add custom skills (ATK)](https://learn.microsoft.com/microsoft-365/copilot/extensibility/build-declarative-agents-add-custom-skills#add-a-skill-to-your-agent)); `wiqd plugin add skill` "scaffolds `appPackage/skills/contract-analysis/SKILL.md` and registers it in `agentSkills[]`" ([Build plugins for Copilot Cowork](https://learn.microsoft.com/microsoft-365/copilot/cowork/cowork-plugin-development)); TypeSpec projects use `main.tsp` at the project root; toolkit pipelines are `m365agents.yml` and `m365agents.local.yml` ([Agents Toolkit CLI](https://learn.microsoft.com/microsoftteams/platform/toolkit/microsoft-365-agents-toolkit-cli#supported-commands)). Package size limits are a 10 MB app package for Agents Toolkit (directory only; `.zip` not supported) and a ≤50 MB `.zip` upload in Agent Builder ([Custom skills in declarative agents](https://learn.microsoft.com/microsoft-365/copilot/extensibility/declarative-agent-skills)).

### Install CLI commands

Two CLIs exist. The Microsoft 365 Agents Toolkit CLI installs with `npm install -g @microsoft/m365agentstoolkit-cli` and exposes `atk doctor|new|add|auth|entra-app|env|install|launchinfo|list|provision|deploy|package|validate|publish|preview|update|upgrade|collaborator|uninstall`; skills are added with `atk add skill --name skill-name --description description` or `atk add skill --from PATH_TO_SKILL`, templates enumerated with `atk list templates` and `atk list samples`, and a package sideloaded with `atk install --file-path "C:/Users/myuser/myPackage.zip" --scope Personal` ([Agents Toolkit CLI](https://learn.microsoft.com/microsoftteams/platform/toolkit/microsoft-365-agents-toolkit-cli#supported-commands); [Add custom skills (ATK)](https://learn.microsoft.com/microsoft-365/copilot/extensibility/build-declarative-agents-add-custom-skills#add-a-skill-to-your-agent)). ### MCP configuration

MCP is consumed in two ways. Inside a declarative agent, an action plugin with `runtimes[].type` of `RemoteMCPServer` and an MCP server spec with `url` and `mcp_tool_description` (new in plugin schema 2.4); "MCP and API plugins are supported as actions within declarative agents. They aren't enabled as standalone experiences in Microsoft 365 Copilot" ([Plugin manifest schema 2.4](https://learn.microsoft.com/microsoft-365/copilot/extensibility/plugin-manifest-2.4); [MCP and API plugins for declarative agents](https://learn.microsoft.com/microsoft-365/copilot/extensibility/overview-plugins)). Inside the app manifest, `agentConnectors[]` entries carry `toolSource.remoteMcpServer` with `mcpServerUrl`, an optional `mcpToolDescription.file` and `authorization` of type `OAuthPluginVault`; "`wiqd plugin create` pins the package to `manifestVersion: "1.29"` ... At 1.29, `agentConnectors[]` entries are URL-only and `mcpToolDescription` is optional" ([Build plugins for Copilot Cowork](https://learn.microsoft.com/microsoft-365/copilot/cowork/cowork-plugin-development)). Tenant admins govern MCP servers alongside plugins and skills in **Agents > Tools > Registry**, and marketplace policy 1140.3.2 applies to "Declarative Agents integrating MCP" ([Certification policies](https://learn.microsoft.com/legal/marketplace/certification-policies#1140-apps-and-agents-for-microsoft-365-and-copilot)).

### How to verify a candidate is real

The reliable fingerprints of an M365 Copilot extension in source form are a `manifest.json` containing `"copilotAgents"`, `"agentSkills"` or `"agentConnectors"`; a sibling `declarativeAgent*.json` whose `"version"` is `"v1.x"` and whose `$schema` points at `developer.microsoft.com/json-schemas/copilot/declarative-agent/`; a plugin JSON with `"schema_version": "v2.x"` and `"runtimes"`; or a `main.tsp` using `@agent`/`@instructions`. Validate offline with `wiqd agent validate`, which "runs the Microsoft Validation Layer — the same engine the platform uses to accept a manifest", or `atk validate` ([Declarative agent schema 1.9](https://learn.microsoft.com/microsoft-365/copilot/extensibility/declarative-agent-manifest-1.9)). Trust signals are tenant-authenticated: the admin center shows "Certification" versus publisher attestation per agent, and marketplace listings pass certification policy 1140. The classifier rule to separate products is `.github/skills/**/SKILL.md` or `.github/copilot-instructions.md` for GitHub Copilot, `manifest.json` with `agentSkills`/`copilotAgents` or `declarativeAgent*.json` for Microsoft 365 Copilot, and `AgentManifest.yaml` plus `PackageManifest.yaml` for Security Copilot; a repo such as `microsoft/wiqd` can be both. Note that the docs tree at `https://learn.microsoft.com/microsoft-365/copilot/extensibility/` was restructured during 2026: the old `agents-are-apps` URL now serves plugin content, so re-verify page titles, not just URLs.

### Skill, plugin and extension formats and manifest filenames

GitHub Docs states "The Agent Skills specification is an open standard" and links `https://github.com/agentskills/agentskills` ([About agent skills](https://docs.github.com/en/copilot/concepts/agents/about-agent-skills)). The file "must be named `SKILL.md`" with YAML `name` (required, lowercase with hyphens, typically matching the directory), `description` (required), optional `license` and `allowed-tools` (for example `shell`, with a warning not to pre-approve `shell`/`bash` unless the skill is reviewed) ([Add skills (cloud agent)](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills)); VS Code adds `argument-hint`, `user-invocable` (default `true`), `disable-model-invocation` (default `false`) and experimental `context: fork`, and surfaces skills as slash commands such as `/webapp-testing` ([VS Code: Agent skills](https://code.visualstudio.com/docs/agent-customization/agent-skills)). Support shipped **December 18, 2025** for the coding agent, Copilot CLI and VS Code Insiders, with stable VS Code "early January" 2026, and `.claude/skills` was picked up automatically from day one ([github.blog changelog 2025-12-18](https://github.blog/changelog/2025-12-18-github-copilot-now-supports-agent-skills/)).

The other customization units, per the authoritative cheat sheet, are repository instructions `.github/copilot-instructions.md`; path-specific `.github/instructions/**/*.instructions.md` (frontmatter `applyTo`, plus `name`/`description` in VS Code); agent files `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` and `REVIEW.md` for code review; prompt files `.github/prompts/*.prompt.md`; custom agents `.github/agents/AGENT-NAME.md` or `.agent.md` (which replaced VS Code's `.chatmode.md` custom chat modes, migrated by rename); hooks `.github/hooks/*.json`; and `mcp.json` ([Customization cheat sheet](https://docs.github.com/en/copilot/reference/customization-cheat-sheet); [VS Code: Custom agents](https://code.visualstudio.com/docs/copilot/customization/custom-chat-modes)). Custom agent frontmatter requires `description` and accepts `name`, `target` (`vscode` | `github-copilot`), `tools`, `model`, `disable-model-invocation`, `user-invocable`, `mcp-servers` (cloud agent only) and `metadata`, with a 30,000-character body limit ([Custom agents configuration reference](https://docs.github.com/en/copilot/reference/custom-agents-configuration)). Plugins are "installable packages that extend Copilot with reusable agents, skills, hooks, and integrations" ([About plugins](https://docs.github.com/en/copilot/concepts/agents/about-plugins)). The Agent Plugins 1.0 manifest is `plugin.json` at the plugin root with required `$schema` (the 1.0.0 or 1.1.0 URL, `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json` or `https://agent-plugins.org/schemas/1.1.0/plugin.schema.json`) and `name` (1–64 chars), fixed component locations `skills/<dir>/SKILL.md` and `mcp.json` at root, and Copilot-specific pieces under `com.github.copilot/` (`agents/`, `commands/`, `rules/`, `hooks/hooks.json`, `lsp.json`); a legacy Copilot plugin format with no `$schema` is also accepted, and MCP transports are `stdio`, `streamable-http`, `sse` ([CLI plugin reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference)). "The `marketplace.json` file is the only required component of a plugin marketplace", located in `.github/plugin/`, and "Copilot CLI looks in `.claude-plugin/`" as well, with fields `name`, `owner`, `metadata` and `plugins[]` (`name`, `description`, `version`, `source`) ([Creating a plugin marketplace](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/plugins-marketplace)). The `excludeAgent` frontmatter field for `.instructions.md`, present in earlier docs, is absent from the current pages and its status could not be confirmed.

### MCP configuration

Configuration is per surface. IDEs use `mcp.json` ("path varies by IDE"; `.vscode/mcp.json` is the conventional VS Code workspace path but was not re-verified in this session). Copilot CLI uses `~/.copilot/mcp-config.json`, `~/.copilot/mcp-oauth-config/`, `~/.copilot/mcp-secrets/`, `copilot mcp add` and the `/mcp` panel ([CLI config directory reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-config-dir-reference)). The cloud agent is configured in repository Settings > "Code, planning, and automation" > Copilot > MCP servers with a JSON object whose top-level key is `mcpServers`; each server has `type` (`local`, `stdio`, `http`, `sse`), `command`/`args`/`env` or `url`/`headers`, and a required `tools` list (`"*"` for all); secrets must be Agents secrets prefixed `COPILOT_MCP_` and substituted as `$VAR`, `${VAR}` or `${VAR:-default}`; only tools are supported, OAuth remote servers are not, and code review requires `annotations.readOnlyHint: true` ([Configure MCP servers (cloud agent)](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/configure-mcp-servers)). Custom agents can embed an `mcp-servers` property (cloud agent only; `${{ secrets.NAME }}`), processed after out-of-the-box configs and before repository settings ([Custom agents configuration](https://docs.github.com/en/copilot/reference/custom-agents-configuration)). Plugins carry `mcp.json` at the root. The "MCP servers in Copilot" policy is disabled by default for Business and Enterprise ([About MCP](https://docs.github.com/en/copilot/concepts/context/mcp)); the relationship between the GitHub MCP Registry and registry.modelcontextprotocol.io was not established.

### How to verify a candidate is real

A skill directory must contain `SKILL.md` with `name` (lowercase-hyphen, matching the directory) and `description`, under `.github/skills/`, `.claude/skills/`, `.agents/skills/` or a plugin's `skills/`; validate with `gh skill preview OWNER/REPO SKILL` and `gh skill publish --dry-run`. A custom agent is `.github/agents/<name>.agent.md` with required `description` and a body ≤30,000 characters. A plugin has `plugin.json` at its root and is listed in a `marketplace.json` under `.github/plugin/` or `.claude-plugin/`; confirm with `copilot plugin marketplace add OWNER/REPO` then `copilot plugin marketplace browse <name>`. Catalog membership means presence in `https://awesome-copilot.github.com/llms.txt`, the awesome-copilot `marketplace` branch manifest, or `github/copilot-plugins` `.github/plugin/marketplace.json`. `gh skill install`'s provenance frontmatter lets an installed skill be traced to a commit. Red flags are "Copilot Extension" GitHub App listings and `allowed-tools: shell`/`bash` in unreviewed skills; GitHub itself warns that "Skills are not verified by GitHub and may contain prompt injections, hidden instructions, or malicious scripts" ([Add skills (cloud agent)](https://docs.github.com/en/copilot/how-tos/copilot-on-github/customize-copilot/customize-cloud-agent/add-skills)). To keep the two Copilots apart in automated search, drop hits from `learn.microsoft.com/microsoft-365/copilot/*` or mentioning "Copilot Studio", "declarative agent", "Agents Toolkit" or "Agent Store", and keep hits mentioning `docs.github.com/en/copilot`, `code.visualstudio.com/docs/agent-customization`, `.github/skills`, `.agent.md`, `copilot plugin install` or `gh skill`.

### Skill, plugin and extension formats and manifest filenames

A skill is `SKILL.md`, which "starts with YAML frontmatter"; "Extra keys are ignored." Fields are `name` (defaults to directory name), `description` (defaults to first body paragraph), `when-to-use` (alias `when_to_use`), `paths`, `allowed-tools`, `argument-hint`, `user-invocable` (default `true`), `disable-model-invocation` (default `false`) and `metadata` (`author`, `short-description`); `model`, `effort`, `license` and `compatibility` are accepted but not applied ([docs.x.ai/build/features/skills-plugins-marketplaces](https://docs.x.ai/build/features/skills-plugins-marketplaces)). xAI's docs never mention agentskills.io or the Agent Skills standard by name, and Grok, Grok Build and xAI do not appear on the agentskills.io Client Showcase as of 2026-10-24 ([agentskills.io/clients](https://agentskills.io/clients)); the format is nonetheless de facto compatible, and `when-to-use` is the Grok-specific key that Browser Use cites as a reason to keep a separate Grok skill copy ([browser-use/plugins README](https://github.com/browser-use/plugins)). A plugin bundles skills, agents, hooks, MCP servers and LSP servers in `skills/` (`SKILL.md`), `commands/`, `agents/`, `hooks/hooks.json`, `.mcp.json` and `.lsp.json`, with "An optional `plugin.json` manifest" that "adds metadata or overrides component paths"; per CONTRIBUTING.md, local plugins include "a valid `.grok-plugin/plugin.json` manifest (`.claude-plugin/plugin.json` is also accepted for Claude-ecosystem plugins)" ([README](https://github.com/xai-org/plugin-marketplace); [CONTRIBUTING.md](https://github.com/xai-org/plugin-marketplace/blob/main/CONTRIBUTING.md)). The `.grok-plugin/plugin.json` field schema is not published on docs.x.ai or in the README; only its existence and that `grok plugin validate .` checks it are confirmed. The catalog schema has top-level `name`, `description`, `owner.name` and `plugins[]` with `name`, `source`, `description`, `category`, `homepage`, `keywords` ("Terms that suggest this plugin for a request"), `domains` ("Hosts/URLs that suggest this plugin when pasted"), `version`, `author` and `tags`; one third party notes it has "**no** `metadata.version`" unlike Claude's ([README](https://github.com/xai-org/plugin-marketplace); [everyinc/compound-engineering-plugin plan](https://github.com/everyinc/compound-engineering-plugin/blob/786ac0194183fadc3d0e2525b2ba6d40353926d3/docs/plans/2026-07-09-001-feat-grok-plugin-support-plan.md)). ### Directory load paths

Skills load from project `./.grok/skills/` (walked up to the repo root), user `~/.grok/skills/`, `~/.agents/skills/` and `~/.agents/commands/`, any enabled plugin's `skills/` directory, and extra paths under `[skills] paths` in `~/.grok/config.toml`; user-invocable skills appear as slash commands `/<skill-name>`, with the qualified form `/local:commit` on collision ([docs.x.ai/build/features/skills-plugins-marketplaces](https://docs.x.ai/build/features/skills-plugins-marketplaces); [docs.x.ai/build/modes-and-commands](https://docs.x.ai/build/modes-and-commands)). ### MCP configuration

MCP servers are TOML `[mcp_servers.<name>]` tables, with project `.grok/config.toml` (each one from cwd up to the git root; a same-named project server "replaces it entirely") overriding user `~/.grok/config.toml`, and lower-priority compat sources `~/.claude.json`, `.cursor/mcp.json` and project `.mcp.json` unless `[compat.claude] mcps = false` or `[compat.cursor] mcps = false`; examples are `[mcp_servers.filesystem]` with `command = "npx"`, `args`, `env = { API_KEY = "${MY_API_KEY}" }`, `startup_timeout_sec = 30`, `tool_timeout_sec = 6000`, and `[mcp_servers.linear]` with `url = "https://mcp.linear.app/mcp"` and `headers`; OAuth tokens sit in `~/.grok/mcp_credentials.json` and logs in `~/.grok/logs/mcp/<server>.stderr.log` ([docs.x.ai/build/features/mcp-servers](https://docs.x.ai/build/features/mcp-servers)). The CLI offers `grok mcp add <name> -- <command> [args]`, `grok mcp add --transport http <name> <url>` ("OAuth is handled automatically"), `--header`, `--scope project`, `grok mcp list`, `grok mcp remove <name>`, `grok mcp doctor [name]`, and since v0.2.113 `grok mcp enable`/`disable`; the `/mcps` TUI tab toggles with Space and authenticates with `i` ([docs.x.ai/build/features/mcp-servers](https://docs.x.ai/build/features/mcp-servers); [x.ai/changelog/build](https://x.ai/changelog/build)). Plugins ship MCP as `.mcp.json` with the Claude-style `{"mcpServers": {…}}` wrapper, which Browser Use notes Grok requires ([browser-use/plugins README](https://github.com/browser-use/plugins)). SSE transport support is undocumented. Hooks are JSON files in `~/.grok/hooks/` and `<project>/.grok/hooks/` across 14 events, with `PreToolUse` the only blocking one ([docs.x.ai/build/features/hooks](https://docs.x.ai/build/features/hooks)).

### How to verify a candidate is real

In descending precision: (a) is it in the official catalog, which implies SHA pinning and code-owner review; (b) does `grok plugin validate <path>` pass; (c) is the source under the vendor's official org, which is xAI's own "source legitimacy" review criterion; (d) does `SKILL.md` have valid frontmatter with `name`/`description` and ideally `when-to-use`; (e) does the README show a Grok install snippet; and (f) is it free of the security red flags xAI lists for rejection, namely `curl | bash`, remote `eval`, secret exfiltration, over-broad hooks, obfuscation and "Prompt injection planted in `SKILL.md`" ([CONTRIBUTING.md](https://github.com/xai-org/plugin-marketplace/blob/main/CONTRIBUTING.md)). The catalog's `keywords`, `domains` and the generated `plugin-index.json` (which lists each plugin's skills, commands, agents, MCP servers, hooks and LSP servers, and whose entries "clients ignore" when the `sha` no longer matches) are machine-readable inputs; the index's exact per-plugin schema was not parsed. Because Grok reads `.claude-plugin/marketplace.json` natively, every Claude Code plugin marketplace on GitHub is effectively a Grok marketplace, so a "find Grok skills" workflow should search Claude Code and Agent Skills corpora first and boost for `.grok-plugin/` and `grok plugin install` signals. docs.x.ai exposes `.md` twins and an index at `https://docs.x.ai/llms.txt` (24 `build/` pages), so polling `https://docs.x.ai/build/features/skills-plugins-marketplaces.md` and the raw marketplace JSON is cheap change detection.

## The vendor-neutral layer: one spec, one context file, one installer, and 46 adopters

### The Agent Skills specification

The spec lives at `https://agentskills.io/specification` with source at `https://github.com/agentskills/agentskills` (**25.3k stars**, 1.9k forks, 145 commits; code Apache 2.0, docs CC-BY-4.0), and its README says the format "was originally developed by Anthropic and later released as an open standard" ([GitHub agentskills/agentskills](https://github.com/agentskills/agentskills)). The layout is `skill-name/` containing `SKILL.md` (required) plus optional `scripts/`, `references/` and `assets/`. Frontmatter has two required fields, `name` (max 64 characters, lowercase letters, numbers and hyphens, no leading, trailing or consecutive hyphens, "Must match the parent directory name") and `description` (1–1024 characters), and four optional ones, `license`, `compatibility` (max 500 characters, free text such as `compatibility: Requires git, docker, jq, and access to the internet`, and "Most skills do not need the `compatibility` field"), `metadata` (string-to-string map, the sanctioned vendor extension point) and `allowed-tools` (space-separated, "Experimental", for example `allowed-tools: Bash(git:*) Bash(jq:*) Read`) ([agentskills.io/specification](https://agentskills.io/specification)). Progressive disclosure is prescribed in three stages: metadata (~100 tokens, loaded at startup for all skills), instructions (< 5000 tokens recommended, loaded on activation; "Keep your main `SKILL.md` under 500 lines") and resources loaded on demand. The reference validator is `skills-ref validate ./my-skill`, a Python package the repo itself labels "intended for demonstration purposes only" ([GitHub skills-ref](https://github.com/agentskills/agentskills/tree/main/skills-ref)). The specification page carries no version number, so a tool should record the fetch date rather than a version; whether a versioned changelog exists elsewhere on the site was not verified, and no evidence was found that the spec has been donated to the Agentic AI Foundation or any standards body.

The Client Showcase at `https://agentskills.io/clients` listed **46 adopters** as of the 2026-10-23 cache, including Claude Code, Claude (claude.ai), ChatGPT & Codex (`https://developers.openai.com/codex/skills/`), Gemini CLI (`https://geminicli.com/docs/cli/skills/`), GitHub Copilot (`https://docs.github.com/en/copilot/concepts/agents/about-agent-skills`), VS Code, Cursor, Kiro, Junie, OpenHands, OpenClaw, Factory, Amp, Letta, Roo Code, Hermes Agent, OpenCode, Goose, Spring AI, Laravel Boost, Pulumi Neo, Snowflake Cortex Code, Databricks Genie Code, Mistral AI Vibe, Qodo and TRAE ([agentskills.io/clients](https://agentskills.io/clients)). Listing is opt-in by pull request, requires that the product "be publicly available and able to discover and execute skills today", and needs logo files plus an entry in `docs/snippets/clients.jsx` ([CONTRIBUTING.md](https://github.com/agentskills/agentskills/blob/main/CONTRIBUTING.md)). Absence is therefore not evidence of non-support: Antigravity, Grok Build, Windsurf/Devin Desktop, Devin, Cline, Zed, Kimi Code CLI, Qwen Code and Continue all document SKILL.md support but were not on the showcase. Microsoft 365 Copilot is also absent from the list despite consuming the format inside app packages.

### AGENTS.md

`AGENTS.md` is "a simple, open format for guiding coding agents, used by over 60k open-source projects. Think of it as a README for agents"; it has no required fields, no schema and no tooling, and "The closest AGENTS.md to the edited file wins; explicit user chat prompts override everything" ([agents.md](https://agents.md/)). It emerged from OpenAI Codex, Amp, Google Jules, Cursor and Factory in August 2025 and was donated by OpenAI to the Linux Foundation's Agentic AI Foundation on **December 9, 2025**, co-founded "alongside Anthropic and Block, and with the support of Google, Microsoft, AWS, Bloomberg, and Cloudflare", with MCP and goose as the other founding contributions ([OpenAI announcement](https://openai.com/index/agentic-ai-foundation/)). The repo is `https://github.com/agentsmd/agents.md` (25.1k stars, 1.9k forks, created Aug 19, 2025) ([GitTrend page for agentsmd/agents.md](https://gittrend.io/repo/agentsmd/agents.md)); the site's example count links to the GitHub code search `path:AGENTS.md NOT is:fork NOT is:archived`, and the 60,000 figure is that search count as cited by OpenAI and the site, not independently reproduced. Readers named on agents.md include Factory, Codex, Warp, UiPath, opencode, goose, Amp, Ona, Gemini CLI (via `settings.json` `context.fileName`), VS Code, Cursor, Zed, Devin, Windsurf, RooCode, Junie, Kilo Code, Augment Code, Aider, GitHub Copilot's coding agent and Jules. Byte caps differ: Codex concatenates up to `project_doc_max_bytes` (32 KiB default) and reads `AGENTS.override.md` first at each level ([Codex AGENTS.md guide](https://developers.openai.com/codex/guides/agents-md)); Devin includes "up to 16 KiB (16,384 bytes) from the beginning of each `AGENTS.md` file" ([Devin docs](https://docs.devin.ai/onboard-devin/agents-md)); Zed reads the first match of `.rules`, `.cursorrules`, `.windsurfrules`, `.clinerules`, `.github/copilot-instructions.md`, `AGENT.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md` ([Zed rules docs](https://zed.dev/docs/ai/rules)). The distinction every adopter draws is the same: AGENTS.md and its siblings (`CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`) are always-on context, skills are on-demand procedures. For a discovery tool, `AGENTS.md` is a signal that a repo is agent-ready, not a distributable unit.

### The Agent Plugins schema

A second vendor-neutral manifest is emerging around the skills spec. The Agent Plugins specification at `https://agent-plugins.org/` (repo `https://github.com/agentplugins/agent-plugins-spec`, spec text at `https://github.com/agentplugins/agent-plugins-spec/blob/main/spec/1.0.0.md`, published 6 Aug 2026) was refined into 1.0.0 by representatives from "AWS, Anysphere, GitHub, Microsoft, OpenAI, and Vercel", with initial TSC maintainers from "AWS, Cursor, Microsoft, OpenAI, and Vercel" and launch clients "ChatGPT and Codex, Cursor, GitHub Copilot, Kiro, and VS Code" ([Vercel: Introducing Agent Plugins](https://vercel.com/blog/introducing-agent-plugins)). Its manifest is `plugin.json` at the plugin root with `$schema` set to `https://agent-plugins.org/schemas/1.0.0/plugin.schema.json` (or the 1.1.0 URL), required `name`, optional `version`, `description`, `author`, `homepage`, `repository`, `license`, `keywords[]` and an `extensions{}` object keyed by reverse-domain namespaces (`com.openai`, `com.github.copilot`), with fixed component locations `skills/<dir>/SKILL.md` and `mcp.json` at root using `https://agent-plugins.org/schemas/1.0.0/mcp.schema.json` ([CLI plugin reference](https://docs.github.com/en/copilot/reference/copilot-cli-reference/cli-plugin-reference); [OpenAI "Package your plugin"](https://developers.openai.com/plugins/build/plugins.md)). Codex documents it as the portable manifest, GitHub Copilot CLI and VS Code accept it alongside Claude and legacy formats, and Microsoft's `atk import openplugin` and `wiqd plugin import` read it (after moving `plugin.json` to `.plugin/plugin.json` and renaming `mcp.json` to `.mcp.json`). The cross-platform researcher did not fetch agent-plugins.org or its schema file directly, so its governance beyond the Vercel announcement is known only from that post and from the `$schema` URLs in vendor docs. Alongside it, the `.agents/` namespace is becoming the neutral root: `.agents/skills/`, `.agents/plugins/marketplace.json` (Codex), `~/.agents/commands/` (Grok), `.agents/mcp_config.json` (Antigravity).

### Cross-agent installers and directories

Vercel's `skills` CLI is the only installer that is genuinely multi-agent at scale. Released January 20, 2026 as npm package `skills` (MIT, Node.js 22.20+), it "Supports **OpenCode**, **Claude Code**, **Codex**, **Cursor**, and 75 more" ([Vercel changelog](https://vercel.com/changelog/introducing-skills-the-open-agent-skills-ecosystem); [README (raw)](https://raw.githubusercontent.com/vercel-labs/skills/main/README.md)). Commands are `npx skills add <owner/repo>` (options `-g, --global`, `-a, --agent`, `-s, --skill`, `-l, --list`, `--copy`, `-y, --yes`, `--all`), `npx skills find [query]` (including `--owner vercel`), `npx skills list`, `npx skills use <source>@<skill> --agent <agent>`, `npx skills check`, `npx skills update [skills...]`, `npx skills remove [skills...]`, `npx skills init [name]` and `npx skills experimental_sync` (skills shipped inside npm dependencies, tracked in `skills-lock.json` per `https://github.com/antfu/skills-npm/blob/main/SPEC.md`); sources may be `owner/repo`, an Azure Repos URL, any git URL or a local path; telemetry is disabled with `DISABLE_TELEMETRY=1` or `DO_NOT_TRACK=1` ([docs/commands.md](https://raw.githubusercontent.com/vercel-labs/skills/main/docs/commands.md); [GitHub vercel-labs/skills](https://github.com/vercel-labs/skills)). Its `docs/agents.md` table is the most complete map of per-agent directories (for example Cursor `.agents/skills/` and `~/.cursor/skills/`, Gemini CLI `.agents/skills/` and `~/.gemini/skills/`, GitHub Copilot `.agents/skills/` and `~/.copilot/skills/`, Grok Build `.grok/skills/` and `~/.grok/skills/`, Kiro CLI `.kiro/skills/` and `~/.kiro/skills/`), though roughly half of the 79 rows were elided by the fetch tool, and Vercel's own docs page (last updated 2026-09-15) still says "18+ AI agents", so the repo is the source of truth ([docs/agents.md](https://raw.githubusercontent.com/vercel-labs/skills/main/docs/agents.md); [Vercel docs](https://vercel.com/docs/agent-resources/skills)). Its discovery algorithm walks a container list up to three levels deep, covering `skills/`, `skills/.curated/`, `skills/.experimental/`, `skills/.system/`, `.agents/skills/`, `.claude/skills/`, `.github/`-adjacent vendor dirs and more than fifty dot-directories (`.cursor/`, `.devin/`, `.goose/`, `.grok/`, `.hermes/`, `.kiro/`, `.qwen/`, `.roo/`, `.trae/`, `.windsurf/`, and so on), and also reads skills declared in `.claude-plugin/marketplace.json` or `.claude-plugin/plugin.json` ([docs/creating-skills.md](https://raw.githubusercontent.com/vercel-labs/skills/main/docs/creating-skills.md)). The companion directory skills.sh (`https://skills.sh/<owner>/<repo>/<skill>`, badges at `https://skills.sh/b/<owner>/<repo>`) is a leaderboard with per-skill install counts, for example `vercel-labs/skills/find-skills` at 4.0M installs and `brainstorming` from obra/superpowers at 398.6K, and an all-time total of 1,496,597 ([skills.sh](https://skills.sh/)); it has no documented public API, and `https://skills.sh/llms.txt` returned 404.

Other directories are Claude-centric. tonsofskills.com (Intent Solutions; "2,900 marketplace-visible skills", 435 catalog plugins, 352 agent definitions) states "Claude Code is currently verified-native; other harnesses are shown only after their integration evidence exists", installs via `/plugin marketplace add jeremylongshore/claude-code-plugins` or its own `ccpi` package manager (`pnpm add -g @intentsolutionsio/ccpi`, `ccpi install devops-automation-pack`), and labels upstream mirrors with `.source.json` provenance files ([tonsofskills.com](https://tonsofskills.com/); [GitHub tons-of-skills-marketplace](https://github.com/jeremylongshore/tons-of-skills-marketplace)). claudemarketplaces.com claims "23,600+ skills", "2,700+ marketplaces" and "12,800+ servers" ranked by installs, stars and registry metadata ([claudemarketplaces.com](https://claudemarketplaces.com/)). aitmpl.com (davila7/claude-code-templates, 32.7k stars, "1,908+ components") is the only directory with a documented, versioned, CORS-enabled JSON API at `/api/v1/catalog.json` described by `https://aitmpl.com/openapi.json` ([aitmpl.com](https://aitmpl.com/); [aitmpl.com/openapi.json](https://aitmpl.com/openapi.json)). None of these publishes a per-skill cross-agent compatibility field. Vendor-run hubs with provenance include Hermes Skills Hub (`~/.hermes/skills/.hub/lock.json`) and OpenClaw's ClawHub (`openclaw skills install`, `.clawhub/lock.json`) ([Hermes docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills); [OpenClaw docs](https://docs.openclaw.ai/tools/skills)). There is no neutral skills registry analogous to the MCP Registry (`https://registry.modelcontextprotocol.io/`, API frozen at v0.1 on 2025-10-24), which indexes servers, not skills, although entries such as `ai.agentplaybooks/agentplaybooks` already touch skills ([registry README](https://raw.githubusercontent.com/modelcontextprotocol/registry/main/README.md)).

### Credible multi-agent collections and how to detect compatibility

The credible multi-agent collections are distinguishable by concrete per-agent plumbing rather than README claims. `obra/superpowers` (MIT, created 2025-10-09) ships one `skills/` tree with shims `.agents/plugins/`, `.antigravity-plugin/`, `.claude-plugin/`, `.codex-plugin/`, `.cursor-plugin/`, `.devin-plugin/`, `.hermes-plugin/`, `.kimi-plugin/`, `.muse-plugin/`, `.opencode/`, `.pi/extensions/` and a root `gemini-extension.json` ([GitHub obra/superpowers](https://github.com/obra/superpowers)). `microsoft/azure-skills` ("Official agent plugin providing skills and MCP server configurations for Azure scenarios", MIT, created 2026-02-26) ships `.claude-plugin/`, `.cursor-plugin/`, `gemini-extension.json`, `plugin.json`, `apm.yml`, `.mcp.json` and skills under `.github/plugins/azure-skills/skills/` ([GitHub microsoft/azure-skills](https://github.com/microsoft/azure-skills)). `sickn33/agentic-awesome-skills` publishes a "Stable Skills Manifest v1" (`skills_index.json`, schema `schemas/skills-index.v1.schema.json`) and per-tool installers `npx agentic-awesome-skills --cursor`, `--gemini`, `--codex`, `--antigravity` ([GitHub sickn33/agentic-awesome-skills](https://github.com/sickn33/agentic-awesome-skills)). `anthropics/skills` (created 2025-09-22, `.claude-plugin/`, `skills/`, `spec/`, `template/`; install `/plugin install document-skills@anthropic-agent-skills`) is the canonical example set ([GitHub anthropics/skills](https://github.com/anthropics/skills)). Self-described multi-agent repos not fetched include `K-Dense-AI/scientific-agent-skills`, `seb1n/awesome-ai-agent-skills` and `VoltAgent/awesome-openclaw-skills`. The practical detector scores a repo per agent by (1) a `SKILL.md` under that agent's native project directory, (2) a `SKILL.md` under `.agents/skills/` or `skills/`, which counts for every agent reading the convergent path, (3) a per-agent plugin manifest, (4) `compatibility:` text, and (5) README install commands; because most agents ignore unknown frontmatter keys, vendor extensions can be parsed as hints without rejecting the skill. The relevant GitHub topics are `agent-skills` and `ai-agent-skills`, and the documented code-search syntax (`path:` with globs and regex, `content:`, `NOT is:fork`, `NOT is:archived`) supports constructed queries such as `path:**/SKILL.md NOT is:fork NOT is:archived`, `path:.agents/skills/**/SKILL.md`, `path:.claude-plugin/plugin.json`, `path:.codex-plugin/plugin.json`, `path:gemini-extension.json` and `path:/SKILL\.md$/ content:"allowed-tools"`, none of which were executed in the research sessions ([GitHub Docs code search syntax](https://docs.github.com/en/search-github/github-code-search/understanding-github-code-search-syntax); [topic agent-skills](https://github.com/topics/agent-skills)).

## Conclusion

The practical consequence of this survey is that "which platform is a skill for" has become the wrong first question. Four of the five platforms plus the entire long tail read the same `SKILL.md` from the same `.agents/skills/` directory, GitHub Copilot and Grok Build additionally read `.claude/skills/` and `.claude-plugin/marketplace.json` natively, and Codex accepts `.claude-plugin/marketplace.json` as a legacy-compatible marketplace, so the Claude Code corpus is effectively the shared corpus and the per-platform ecosystems are thin wrappers around it. What still differentiates platforms is governance and packaging: Google and xAI run curated catalogs (an interest form, a SHA-pinned PR queue), GitHub and OpenAI run open marketplaces with explicit "not verified" disclaimers, and Microsoft 365 runs a tenant-admin registry with no public catalog at all. A discovery tool should therefore index once by structure (`SKILL.md` frontmatter validity, load-path placement, plugin manifest presence) and only then annotate per platform using the small set of discriminating markers this report surfaces: `agents/openai.yaml` for Codex, `gemini-extension.json` and the `antigravity.google/schemas/v1/plugin.json` schema for Google, `.github/skills/` and `.agent.md` for GitHub Copilot, `agentSkills`/`agent_skills` in a `manifest.json` or `declarativeAgent.json` for Microsoft 365, and `.grok-plugin/` or `when-to-use` for Grok.

Two trends point at where the layer is heading. The Agent Plugins schema, co-authored by AWS, Cursor, GitHub, Microsoft, OpenAI and Vercel and already read by Codex, Copilot, VS Code and Microsoft's import tools, is doing for plugin packaging what agentskills.io did for skills, and the `.agents/` namespace is becoming the neutral root for skills, plugins, commands and MCP config alike. At the same time there is still no vendor-neutral skills registry with per-skill provenance comparable to the MCP Registry; skills.sh fills that role on the strength of install counts but without an API, and the richest provenance signals (SHA pins, code-owner review, `gh skill install` tree hashes, `.source.json` mirror labels) live inside individual vendor catalogs. Until a neutral registry emerges, verification will remain a structural exercise that each consumer of these ecosystems has to run for itself, and the handful of claims this report leaves flagged as unverified, from Grok's `--trust` flag to the public home of Google's official Antigravity plugins, are exactly the places where that exercise should start.
