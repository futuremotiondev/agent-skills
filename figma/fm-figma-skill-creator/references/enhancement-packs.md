# Enhancement packs

An enhancement pack is a behaviour that many different skills can adopt as one separable unit: instruction steps, output-contract lines, edge cases, a Final gate line, helper code, and a seed case that proves it. "Audit colour contrast" is a skill; "bind a value to the matching token" is a pack.

A pack lives in a master as tagged units. This file is the contract for those tags. `scripts/enhancement-packs.mjs` is its test: `list` reports the units it finds, `strip` removes a pack from a master, and `extract` writes each pack's reference file from a tagged master, so pack text is never copied by hand. The audit master, `examples/fm-spacing-rhythm-audit/SKILL.md`, carries the two shipped packs and supplies every example below.

```bash
node scripts/enhancement-packs.mjs list <SKILL.md> [--pack <name>]...
node scripts/enhancement-packs.mjs strip <SKILL.md> --pack <name> [--pack <name>]... [--out <file>]
node scripts/enhancement-packs.mjs extract <SKILL.md> [--pack <name>]... [--phrase "<Phrase:>"]
```

Packs resolve from `enhancements/<name>/pack.json` beside the `scripts` folder, or from `--enhancements <dir>`. Without `--pack`, every pack in that folder is used. `strip` writes to standard output when `--out` is absent.

## Pack folder layout

```text
enhancements/
  <name>/
    pack.json        hand-maintained; the declarations below
    enhancement.md   generated by extract; never edited by hand
```

`extract` writes `enhancement.md` on every run and `pack.json` only when it is absent (a skeleton, with the phrase from `--phrase`). It writes no timestamp, so a second run changes nothing. `enhancement.md` opens with the pack's name, phrase, cost, requires, conflicts, surfaces, and seed case, then gives one level-three heading per unit ("Unit n: kind in section"), the unit's anchor as JSON, and the unit's text in a fence.

## pack.json

| Field | Meaning | token-conformance |
| --- | --- | --- |
| `name` | Folder name and code-region name | `"token-conformance"` |
| `phrase` | The prose tag, written with its colon | `"Token mode:"` |
| `codeRegion` | The name in `// enhancement: <name> begin` and `end` | `"token-conformance"` |
| `templateLines` | Exact lines inside the fenced report template that belong to the pack | `"- Bound values: <n> passed"` and nine more |
| `proseSentences` | Exact prose sentences that belong to the pack but do not start with the phrase | the Output contract's "Token mode adds these lines: …" |
| `lineRewrites` | Whole lines the pack changes rather than adds: `{ "from", "to" }`, `from` being the line with the pack | the `let MODE` line |
| `descriptionSentences` | Sentences of the frontmatter `description` that belong to the pack | `"With spacing tokens in the file it audits against those tokens and binds values to the matching variable."` |
| `tags` | Entries of `metadata.tags` that belong to the pack | `"tokens"`, `"variables"` |
| `requires` | Behaviours the pack depends on (vocabulary below) | `[]` |
| `conflicts` | Behaviours the pack cannot be combined with | `[]` |
| `cost` | What the pack adds to a run, in calls and credits | "one extra collect call (discover) when the file has tokens; about 22 to 24 credits per page audit either way" |
| `seedCase` | The seed file, the nodes that prove the pack, the expected scope, and optional `proofs` | `fm-spacing-audit-seed`, five nodes, scope 2 |
| `surfaces` | Optional: the editor types the pack's code and instructions run in, from `figma-design`, `figma-make`, `figma-spec`; a non-empty array when present | absent, which means `["figma-design", "figma-make"]` |

`revert` declares the phrase `"Revert:"`, the code region `revert`, one template line, one prose sentence ("Revert adds: …"), no rewrites, description sentences, or tags, `requires: ["confirm-tiered"]`, and the proofs `revertClean` and `revertAfterEdit` on `Token card`. Every entry of `templateLines`, `proseSentences`, `descriptionSentences`, and `tags` is a non-empty string.

## Units

A unit is the smallest piece of a pack the tools move. Each unit has a kind, a start and end line, a column (for sentence, prose-sentence, description-sentence, and tag units), its text, and an anchor:

| Kind | What it covers |
| --- | --- |
| `code-region` | A region inside a helper, markers included |
| `fence` | A whole helper fence whose code is one region |
| `block` | A prose line that starts with the phrase, with its continuation lines |
| `heading-block` | A heading that starts with the phrase, to the next heading of the same or higher level |
| `sentence` | A sentence that starts with the phrase mid-line |
| `prose-sentence` | One declared prose sentence |
| `template-line` | One declared line of the fenced report template |
| `line-rewrite` | One declared line the pack rewrites |
| `description-sentence` | One declared sentence of the frontmatter description |
| `tag` | One declared entry of `metadata.tags` |

The anchor is `{ section, helper, after }`. `section` is the text of the nearest level-two heading above the unit (`frontmatter` for description sentences and tags). `helper` is the name of the helper fence that holds the unit, or `null`. `after` is the exact text of the nearest non-blank line before the unit; for a sentence or prose-sentence unit it is the sentence before it on the same line, for a description sentence the sentence before it in the description, and for a tag the entry before it in the list (`null` for the first).

## The tag scope rule

### (a) Code regions

Code units run from `// enhancement: <name> begin` to `// enhancement: <name> end`, both marker lines included. Regions never nest and never interleave with a region of another pack; the tools stop with an error when they do, or when a marker has no partner. A region that starts on the line after the `// helper:` marker and ends on the fence's last code line is a whole-fence unit: stripping it removes the fence and the blank line before it. The revert helper is the example:

````markdown
```javascript
// helper: revert
// enhancement: revert begin
// Revert: restore each applied change's previous value or binding, only where the layer still reads what apply set.
...
return { reverted, skipped };
// enhancement: revert end
```
````

A fragment region stays a `code-region`, such as the bind branch inside the apply helper:

```javascript
    // enhancement: token-conformance begin
    // A bind fix only binds (the binding sets the value; without a `value` it records the post-bind read); a missing variable leaves the node untouched.
    if (f.variableId) {
      ...
    }
    // enhancement: token-conformance end
```

### (b) Block units

A prose line whose text, after its indentation, list marker (including a task box such as `- [ ]`), bold markers, or heading hashes, starts with the pack phrase is a block unit: the line plus every continuation line up to the next blank line. A continuation line is more indented than the unit's first line, as a blockquote or a wrapped line under a list item is. The first line that is not more indented ends the block, even with no blank line before it: a line at the same indent, a new list item, or a heading stays outside the unit. Step 5 of "Before you start" is one block of three lines, the blockquote and the indented line included:

```markdown
5. **Token mode: choose the mode once.** If any spacing tokens exist (`spacingCollection` is not null), ask, ...
   > This file has spacing tokens (2 to 160 px, plus negative tokens to -24). Audit against 1. the system's tokens ...
   Wait for the answer, then collect again in the chosen mode. Default to 1 when the user says "just audit". ...
```

Only the phrase with its colon tags a unit. The same words without the colon are ordinary prose, so "Revert the last change by hand if the script stops." and "- Token mode is chosen once per run and never changes mid-run." survive every strip untouched. A pack sentence that cannot start with the phrase is declared in `proseSentences` instead (rule f).

### (c) Heading blocks

A heading whose text starts with the phrase is a heading-block unit: the heading and everything after it up to the next heading of the same or higher level (or a target marker). The Do and do not section opens with one:

```markdown
### Token mode: bind, do not hard-code

- **Do:** "Padding left 10 → bind Space/300 (Compact)."
- **Do not:** "Padding left 10 → set 8."
```

### (d) Sentence units

The phrase in the middle of a line starts a sentence unit: from the phrase to the end of the sentence. The sentence ends at the first `.`, `?`, or `!` that is followed by a space or the end of the line and is not inside parentheses opened within the sentence. A closing parenthesis that the sentence did not open ends it first: the text before the parenthesis is the unit, and the parenthesis stays. Stripping a sentence unit also removes the one space before the phrase; when there is no space before it (the phrase follows an opening parenthesis, for example), the one space after the sentence is removed instead, if there is one. In the edge case for bound values, the last sentence is the unit:

```markdown
- **Values bound to variables.** Never overwrite an existing binding. In rhythm mode, report the variable name and its resolved value at P2 and suggest changing the variable. Token mode: a bound value passes and is counted on the Bound values line.
```

In "Bind the value (Token mode: only unbound rows) and report it.", the unit is "Token mode: only unbound rows", and stripping it leaves "Bind the value () and report it.". A period inside quotation marks also ends a sentence, so keep sentence units free of quoted sentences. Do not put the phrase inside an inline enumeration such as "a) … b) …", because the enumeration's closing parenthesis ends the unit early and the cut leaves broken text. The phrase must not appear in a table row (a line whose first non-space character is `|`): cutting it would break the table, so the tools stop with an error that names the line. Move the sentence out of the table. A phrase inside a code span (between backticks) is ordinary prose: it starts no sentence unit and raises no table-row error.

### (e) Template lines

Lines inside the fenced report template carry no phrase, because the agent would print it. They are declared in `pack.json` `templateLines` and matched exactly, against the body's non-helper fences only. A declared line must match exactly one line; two matches stop the tools with an error. The revert pack declares one:

```markdown
Previous is the human record; the revert list is the apply result.
```

### (f) Declared changes outside the prose

Four kinds of change cannot carry a phrase and are declared instead.

`proseSentences` are pack sentences in the body's prose that do not start with the phrase. Each entry is matched exactly, outside fences. A declared sentence that the master does not contain is a warning that names it, and nothing is removed for it, as with every other declared item. A declared sentence that matches more than once stops the tools with an error naming the lines, because they cannot know which to cut, and so does one that overlaps a unit the phrase already tags. It is stripped like a sentence unit. The audit master declares two, both in the Output contract paragraph:

```markdown
Token mode adds these lines: Mode (printed in both modes whenever the file has spacing tokens), Bound values (in place of Bound to variables, which rhythm mode keeps), ...; and the Fix column's bind form, "bind Space/200", beside "set 8" for a value with no token within 4.
Revert adds: the After fixes table, whose Previous column holds each layer's value or binding before the snap, and the line naming where the revert list comes from.
```

The first is declared by `token-conformance`, in full in its `pack.json`, and the second by `revert`.

`lineRewrites` replace one whole line, matched exactly and only once, with the line the master has without the pack; the collect helper's first line is the example:

```javascript
let MODE = "discover"; // discover | tokens | rhythm // without the token-conformance pack this reads: let MODE = "rhythm"
```

`descriptionSentences` are removed from the frontmatter `description`, with the space before them (or, at the start of the description, the space after them, as in rule d). `tags` are removed from `metadata.tags`, keeping its quoting and its comma-and-space separator.

### (g) Stripping keeps a working master

`strip` removes the units of each named pack, applies its rewrites, removes its description sentences and tags, and collapses runs of blank lines. The result must validate with 0 errors (`validate-figma-skill.mjs --edition master`) and every helper in it must parse, which `build-skill-editions.mjs` checks before it writes. Stripping `token-conformance` from the audit master leaves the plain rhythm audit with four helpers; stripping `revert` leaves three. A declared item that the master does not contain is reported on standard error and skipped, so a master without the pack, never tagged or already stripped, passes through `strip` unchanged.

### (h) Expanding into a master without an anchor

Expanding a pack into a master puts each unit after its anchor. When a master has no anchor for a unit, prose units go at the end of their section, and the orphan code regions of each helper go into one new `javascript` fence with no `// helper:` marker, opened by the comment `// <pack> regions for <helper>: place by hand`, for example `// token-conformance regions for collect: place by hand`, with one warning per region. That fence is never extracted as a helper. (`expand` is the next tool to build; until then this rule is the specification it follows.)

### (i) Surfaces

The optional `surfaces` field names the editor types the pack's code and instructions run in: `figma-design`, `figma-make`, `figma-spec`. `mcp` is a runtime, never a surface. When present it is a non-empty array of those values; `loadPack` rejects an empty array or any other value. Absent means `["figma-design", "figma-make"]`, so the two shipped packs omit it. A skill's surfaces are the `figma-*` entries in its `metadata.runtimes`; the audit master's are `figma-design` and `figma-make`.

- **Full cover** (every skill surface is in the pack's list): the creator offers the pack normally.
- **Partial cover**: the creator offers it only when the user names it, says in one sentence which surface it will not run on, and requires a surface guard in the helper that prints `skipped in a Spec file`, as probe 1.2 does.
- **No overlap**: the creator does not add it, says why in one sentence, and offers to narrow the skill's surfaces.
- **Presets**: a preset silently leaves out its non-matching members, and the creator lists what it left out.

### (j) Helper form

Pack code regions that are whole helpers follow the helper-form rule: top-level `await`, a final `return`, no function wrapper. The tools never wrap or unwrap code. Fragments inside a helper, such as the six token-conformance regions, are unaffected.

## Requires and conflicts

`requires` and `conflicts` name behaviours from a fixed vocabulary. The tools record them and do not enforce them; the creator reads them when it adds a pack.

| Value | Meaning |
| --- | --- |
| `confirm-tiered` | The skill writes only after the user confirms, applying high-confidence rows and previewing the rest |
| `always-write` | The skill writes without asking |
| `dry-run` | The skill previews every write without changing the canvas |

`revert` requires `confirm-tiered`, because it rebuilds its list from a confirmed apply result. A dry-run pack conflicts with `always-write`.
